3.1Understand the picture before writing the drawing code#

The application now opens a window and responds to its close button. It does not draw a picture yet. Leave the files unchanged while we examine how a few corners can describe a filled shape.

This chapter introduces the jobs of the CPU, shaders, and rasterizer. You only need to understand the order of those jobs; we will teach the exact coordinate rules and API calls when we use them.

3.2A rectangle needs corners, not a list of pixels#

Imagine drawing a filled rectangle on squared paper. You can describe it by marking four corners; you do not have to name every square inside it. A graphics program can make the same kind of description. A vertex is a record describing a corner or another point in a shape. A pixel is one element of the output image’s grid.

We will draw filled shapes as triangles. Three corners define one triangle. Four rectangle corners can be used by two triangles, as the diagram shows. The numbers label the corners; each group of three numbers selects one triangle. This arrangement lets the triangles share two corners.

The diagonal divides the work between the triangles. It is not a line we ask the GPU to draw. The GPU’s edge rules determine which triangle covers each sample along that shared edge, so together the triangles fill the rectangle.

3.3Follow a triangle into the image#

The GPU processes our description in stages. A shader is a small program that runs on the GPU. We will write one shader to place vertices and another to choose colors. The sequence of these programs and the fixed work between them is a graphics pipeline.

First, the vertex shader calculates where each corner belongs. The GPU groups those corners into triangles. It clips away any parts outside the visible area, then finds which image sample locations the remaining triangles cover. Finding that coverage is called rasterization.

Rasterization produces fragments: candidates for color contributions to the image. The fragment shader chooses a color for each contribution. A fragment is not the same thing as a final visible pixel: another triangle may later write the same location. For now, imagine one triangle over a background, so its covered region receives the shader’s chosen color.

The vertex shader does not call the fragment shader. It returns positions. The GPU uses those positions to create the fragment work. This is why changing how a face is colored need not require adding more corners to the rectangle.

3.4Recording work is different from doing it#

Our Odin application runs on the CPU. It describes the drawing work and sends that work to the GPU. A draw call records an instruction; it does not wait until the monitor shows the result. The GPU can draw an earlier frame while the CPU prepares a later one.

We will use a command encoder to build a list of instructions. Finishing the encoder produces a command buffer: the completed list. Submitting gives that list to the device’s queue for execution. Presenting hands the resulting image to the window system for display. We will implement these steps individually when the window connection is ready.

Keep two questions separate as you read the next chapters: “Have we described the work?” and “Have we submitted it for execution?” A correct triangle description cannot change the window until it reaches the GPU and its image is presented.

3.12Challenges#

Optional extensions. The complete game in chapter 23 requires none of these. Work in a separate copy if you want to explore; the next chapter starts from the unmodified result described here.

  1. Plan a diamond marker

    Sketch a diamond from a top, right, bottom, and left corner. List two triangle triplets that cover it. Save the sketch for chapter 10, where you can implement it.

    Check your result: The triangles share one edge and cover the diamond without a gap.

  2. Draw the same shape at two sizes

    Sketch the same triangle on two image grids, one twice as wide and tall as the other. Mark the corners and the area each triangle covers.

    Check your result: The larger image has more covered pixels without needing more corner records.
