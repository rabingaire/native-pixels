2.1From a report to a window#

Your program can call SDL and WebGPU, print their versions, and exit. A desktop application needs to stay running until the user closes it. We will replace the version report with an SDL window and a loop that handles window events.

An event is a notification such as a request to close the window. Before writing the loop, we will learn the variables, decisions, and cleanup notation it uses. This chapter changes only src/main.odin.

2.2Keep values and make decisions#

The first program ran each instruction once and exited. A window needs the program to remember whether it should keep running. That remembered value is a variable. Read this small example before replacing the application file:

running := true creates a variable and lets Odin infer its type. The type is bool, which has two values: true and false. count: int = 0 names the type explicitly; int stores whole numbers. = changes an existing variable, while == compares two values. count += 1 adds one to the current count.

for running repeats its block while running is true. On the third iteration, the if condition succeeds and changes it to false. The next loop check stops repetition. break exits a loop immediately. return leaves the current procedure; leaving main ends our program.

The window code also uses ! for “not”: if !sdl.Init(...) enters the error branch when initialization returns false. fmt.eprintln writes an error message to the terminal. A name declared without a value, such as event: sdl.Event, starts with its type’s zero value.

SDL fills an event variable for us. To let a procedure write into an existing variable, we pass its address with &event. An address tells the procedure where that variable is stored. A value holding an address is called a pointer. We will use pointers whenever a helper needs to change the original data.

defer schedules a call for when its current scope exits. A scope is the region inside a pair of braces. In main, we defer SDL cleanup only after SDL starts successfully. Later defers run first, so destroying the window happens before shutting SDL down. An early return still runs the defers already registered. && means both conditions must hold; || means at least one must hold.

An enumeration, usually called an enum, is a type with named choices. SDL events have choices such as .QUIT. The leading dot lets Odin find the enum type from the surrounding code. A switch chooses a case based on a value. #partial switch lets us handle the event kinds we need and ignore the others.

Window flags are a set of named options. {} is an empty set, {.METAL} contains one option, and flags += {.METAL} adds it. when ODIN_OS == .Darwin includes that code only when compiling for macOS. This choice happens during compilation; ordinary if runs when the program executes.

2.3Give SDL the window work#

SDL creates the window and passes us events from the operating system. Our loop reads those events so closing the window can stop the program. We will use WebGPU for drawing after this loop works. SDL also offers drawing APIs, but this program only uses its window and input facilities.

2.4Replace the probe with a living window#

Replace src/main.odin in full. The program is short enough to see the entire lifetime before we divide it into graphics procedures.

In src/main.odin: Replace the entire file with this listing. Complete file with surrounding code.

sdl.Init({.VIDEO}) initializes the video subsystem and the event facilities it requires. SDL3 returns a boolean here: true means success. Older SDL2 examples often compare an integer result with zero. That check reverses the meaning if copied carelessly into SDL3. On failure, GetError() supplies a useful diagnostic.

All calls that create, show, and destroy this window run from main. On macOS, the METAL flag lets SDL provide the kind of drawing surface the graphics library will need. Other supported desktop platforms do not need an extra graphics flag for this window. The ordinary window flags stay empty for now.

CreateWindow gives us a window handle. ShowWindow asks the operating system to display it, and RaiseWindow asks to bring it forward. A system may refuse to give a background application focus, so a failed raise prints a message but leaves the program running. If showing the window fails, we return through cleanup.

CreateWindow returns an SDL-owned opaque window object that our application must eventually destroy. SDL reads the quoted title as a C string, a sequence of characters with a zero byte marking its end. The string literal used here supplies the form SDL expects.

2.5Events keep the window alive#

PollEvent reads one waiting event and writes it into event. The inner loop calls it until no events remain. An Event can hold data for several kinds of notification; its type field tells us which kind is present. This chapter only checks that field. A close or quit event sets running to false, and the outer loop then stops.

#partial switch is intentional: SDL defines far more event types than we need. Ignoring an unrelated mouse motion does not mean it remains queued forever; polling has already removed it. A single if PollEvent per frame can leave a backlog during an event burst. Draining the queue gives us the latest state before updating the application.

Delay(10) sleeps for roughly ten milliseconds so this empty loop does not consume an entire CPU core. It is temporary pacing, not a graphics clock. For now there is no drawing to wait for, so we pause explicitly between event checks. The native title bar and client area may appear blank, black, or platform-colored here. SDL has not drawn our background; this checkpoint makes no claim about client-area pixels.

2.6Destruction follows dependency order#

The two defer statements establish reverse-order cleanup. The window is destroyed before SDL quits. An early return after a failed window creation still shuts down the successfully initialized subsystem. No failed handle is passed to its destroy function. The rule is to clean up a resource before the resource it depends on.
