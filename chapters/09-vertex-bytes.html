9.1Calculate an address before trusting the image#

An ABI, or application binary interface, is an agreement about how data is represented across a boundary. Here Odin lays out bytes, WebGPU describes how vertex fetch reads them, and WGSL declares the receiving values. Matching field names is not enough; byte offsets, formats, and shader locations must agree.

Each vertex occupies 24 bytes. Vertex number 1 starts 24 bytes after the buffer’s beginning, and its color starts another 8 bytes later: byte 32. Float32x4 asks vertex fetch to decode four 32-bit floating-point values there. A stride of 16 would instead start the next vertex inside the preceding color.

A buffer slot chooses a stream of records. A shader location chooses an input within a particular stage interface. We bind one buffer in slot zero, but read two attributes at locations zero and one. Remembering those separate jobs prevents a large class of apparently mysterious shader errors.

9.2Move geometry out of the shader#

The hard-coded array proved the shader pipeline. It becomes awkward as soon as geometry belongs to the application rather than to shader source. A GPU buffer gives us a persistent region of bytes usable by GPU operations. The CPU owns a native handle, while the implementation chooses suitable backing storage. We cannot assume that storage is simply a CPU array, even on a machine with unified memory.

Add the Vertex struct and three-element VERTICES constant to renderer.odin. The constant is CPU-side data compiled into the program. The WebGPU buffer created from it is a separate object. Change the WGSL vertex entry point to read attributes rather than vertex_index. This deliberately removes the temporary shader array introduced in chapter 8.

9.3Follow one record through all three interfaces#

Odin memoryWebGPU attributeWGSL input
Bytes 0–7: two f32 position valuesOffset 0, Float32x2, location 0@location(0) position: vec2f
Bytes 8–23: four f32 color valuesOffset 8, Float32x4, location 1@location(1) color: vec4f
Next record begins 24 bytes laterarrayStride = 24, stepMode = VertexA new record for the next vertex index

The stride is the distance in bytes from the beginning of one vertex record to the beginning of the next. An attribute’s offset is measured from the beginning of its record. The GPU effectively reads buffer_base + vertex_number × stride + attribute_offset, then interprets those bytes according to the format. The shader location identifies the destination parameter; the parameter’s name is not part of this matching process.

Our struct contains arrays of scalar f32 values. Its position begins at byte zero and its color at byte eight, with size 24. Compile-time assertions make that ABI explicit. Vertex attributes do not inherit WGSL uniform-buffer layout rules: a Float32x4 vertex attribute at byte eight is valid even though a vec4f in a uniform struct requires 16-byte alignment. Confusing vertex-fetch layout with shader memory layout is a frequent source of unnecessary padding and incorrect strides.

attributeCount and attributes describe the array of two attributes. bufferCount = 1 and buffers = &vertex_layout are added to the pipeline’s vertex stage. Buffer slot zero describes one stream of interleaved position/color records. It is independent of shader locations zero and one. Multiple attributes can come from the same buffer slot, as they do here.

9.4Allocate once, upload once#

.Vertex allows vertex fetch from the buffer. .CopyDst allows writes through the queue. Flags are capabilities of the resource, not the operation we happen to perform first. Leaving out CopyDst is a validation error when uploading, even if the buffer size is correct. Buffer allocation by itself does not copy our constant into GPU storage.

QueueWriteBuffer copies the supplied CPU bytes into implementation-managed upload storage as part of the call, with the GPU-visible write ordered through the queue. The local vertices copy exists to supply an addressable range for that call; it can go out of scope afterward. We do not map the vertex buffer, block for GPU completion, or retain a pointer to the local array. The data size is 72 bytes, a multiple of four, satisfying the write operation’s alignment requirement.

Add a vertex-buffer handle to Renderer and release it in renderer_destroy. Inside renderer_frame, bind slot zero immediately after selecting the pipeline and before drawing:

The byte offset is zero and the bound range is the whole vertex array. This establishes which actual buffer supplies the slot whose layout the pipeline already describes. Layout and binding solve different questions: “how are records interpreted?” versus “which storage contains them?”

9.5Interpolate values across the triangle#

The vertex shader returns a struct with a built-in clip position and a user color at location zero. The fragment shader receives the interpolated color at that location. Do not confuse its location zero with the vertex input color at location one: these are different stage interfaces. Locations connect outputs to inputs at a particular stage boundary, not a single global namespace.

The rasterizer interpolates the three vertex colors across the covered triangle. WGSL’s default interpolation is perspective-correct for floating-point user values; all our w values are one, so this reduces to the affine interpolation you expect in 2D. A green region inside the triangle is not another uploaded vertex. It is a color computed from nearby vertex contributions.

9.8Experiments#

These short, optional checks help you test the explanation. Predict the result first, then run the program. Restore the chapter’s baseline before continuing; later chapters assume the supplied checkpoint.

9.10Challenges#

Optional extensions. The complete game in chapter 23 requires none of these. Work in a separate copy if you want to explore; the next chapter starts from this chapter’s supplied baseline.

  1. A second mesh

    Put two independently shaped triangles into one six-vertex buffer, with a different color scheme for each. Update the upload size, bound range, and draw count together.

    Check your result: Both triangles render without changing the 24-byte vertex contract.

  2. An animated color field

    Keep positions fixed and update vertex colors from a CPU-side clock. Add CopyDst only if it is missing, and reuse the buffer allocation.

    Check your result: Colors animate without rebuilding the pipeline or changing triangle positions.
